Vibe LedgerBeta product specification
Product definition

A local-first budgeting layer over Monzo transaction data.

Vibe Ledger groups ordinary categories into three user-controlled monthly allocations: Living, Saving and Fun. It is designed to make the current month and historical spending understandable without turning every subcategory into a hard budget.

Living
50%

Rent, bills, groceries, transport and other necessary spend.

Saving
30%

Saving contributions such as house saving, pots and investments.

Fun
20%

Coffee, restaurants, shopping, cinema, nights out and discretionary spend.

Saving contribution

Putting £200 in a Monzo saving pot and sending £200 to a Moneybox ISA can have the same budget meaning even if the bank represents them differently.

Saving withdrawal

Taking £5,000 out of old savings is not £5,000 of new income. Vibe Ledger records it as a savings withdrawal and keeps the month's budget base unchanged.

Editable monthly allocation

The user can change 50/30/20 for the current month. Historical months retain the targets actually used at the time.

Saving additionally shows net savings movement so a month can be 100% on saving contributions while total savings still fell because older savings were withdrawn.

Runover

Overspending never gets compressed to fit a polite gauge.

One complete line always represents one complete budget. When spending passes 100%, the bar wraps onto another line underneath.

Fun£1,430 / £600 · 238%

£100,000 against a £600 budget remains approximately 167 budget-lengths tall. Rendering may be virtualised, but the proportional scroll distance is preserved.

Trends and search

Historical analysis uses the same categories and stored monthly targets.

Trends

  • Monthly stacked bars for a super-category.
  • Stacks show its ordinary categories.
  • Month-specific target overlay.
  • Multiple super-categories use grouped stacked bars.
  • One category becomes a simple monthly series.

Deterministic search

Examples:

coffee last 6 months
fun over £50
restaurants august

Recognised meaning is always shown as removable filters. No LLM is required.

Local

Transactions, categories, rules, classifications, subscriptions and analytics are intended to live on-device.

Known integration constraint

Monzo's Developer API does not issue refresh tokens to non-confidential clients. The beta must test whether acceptable re-authentication is possible or whether a minimal auth/sync broker is required.

References: https://docs.monzo.com/ · https://docs.monzo.com/open-banking/

Beta boundary

The build target is intentionally narrow.

Included

  • Monzo import
  • Living / Saving / Fun allocation
  • Runover bars
  • Heat map + drill-down
  • Explorer and rules
  • Historical trends
  • Deterministic search
  • Subscriptions

Deferred

  • Generative AI
  • Investment performance
  • Funding-source tracing
  • Automatic pot-purpose alignment
  • Public multi-bank infrastructure
  • Heavy gamification

Build criterion: every number shown to the user must be traceable to the raw transactions and explicit Vibe Ledger classification rules that produced it.
